## 一、模块定位

交付层是 Agent 的"质量检验员 + 报告员"，负责验证执行结果是否达标，生成分层交付报告，管理用户确认。

**核心约束（主心骨）**：
> **三级验证（L1静态→L2动态→L3人工）+ 风险自适应阈值。报告按金字塔原理分层（结论→摘要→详情→建议→风险）。验证通过率阈值由风险等级动态确定，不写死。目标是可验证的，验证结束必须有证据链。**

## 三、模块规则

### DV-001：ResultVerifier — 三级验证

**L1 静态检查**（无需执行）：
- 格式校验、完整性检查
- 快速、零成本

**L2 动态测试**（需要执行）：
- 运行测试用例、检查输出
- 通过率阈值由风险等级动态确定

**L3 人工确认**（需要用户）：
- 高风险操作必须人工确认
- 审批流程通过 ApprovalModule

**风险自适应阈值**：
- 低风险：通过率 ≥ 80%
- 中风险：通过率 ≥ 90%
- 高风险：通过率 ≥ 95%
- 风险等级由 LLM 根据任务描述动态评估

### DV-002：验证报告结构
- 每条验证项有：criterion / level / status / evidence / error / duration
- 整体报告有：overall_status / pass_rate / evidence_chain
- evidence_chain 不可篡改（审计学证据链）

### DV-003：ReportGenerator — 分层报告

**金字塔原理**：
1. **结论**（一句话）
2. **摘要**（关键数据）
3. **详情**（验证项列表）
4. **建议**（改进建议）
5. **风险**（剩余风险）

**分层展示**：
- `user_summary` 层：给普通用户看
- `tech_detail` 层：给技术用户看
- `active_layer` 默认 `summary`

### DV-004：ConfirmationManager — 任务确认
- 任务完成后等待用户确认
- 确认超时处理
- 确认结果记录到审计日志

### DV-005：参数不写死
- 风险等级阈值：由 LLM 根据任务描述动态评估
- 通过率阈值：由风险等级动态确定
- 测试超时时间：由 LLM 根据任务复杂度动态评估
