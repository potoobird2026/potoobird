## 一、模块定位

记忆系统是 Agent 的核心资产，所有用户交互、人格特征、开发标准都存储于此。

**核心约束（主心骨）**：
> **三层记忆架构：第1层人格（HEXACO，只读）+ 第2层核心记忆（SQLite，可读写）+ 第3层标准（Markdown，可优化）。记忆写入必须幂等，读取必须带审计日志。人格加载失败时降级到全50默认值，绝不崩溃。**

## 三、模块规则

### M-001：三层记忆架构

| 层级 | 名称 | 存储 | 读写 | 用途 |
|------|------|------|------|------|
| 第1层 | 人格 (Personality) | `personality.md` | 只读 | HEXACO 六维人格参数 |
| 第2层 | 核心记忆 (Core) | `memory.db` (SQLite) | 可读写 | 用户偏好、历史交互、事实 |
| 第3层 | 标准 (Standard) | `standards/*.md` | 可优化 | 开发规范、流程标准 |

### M-002：人格 Schema 校验
- HEXACO 六维：H(诚实-谦逊)、E(情绪性)、X(外向性)、A(宜人性)、C(尽责性)、O(经验开放性)
- 每维分值范围：0~100
- 校验失败处理：
  - 文件不存在 → 全50默认
  - 解析失败 → 全50默认 + 警告日志
  - 单个维度非法 → 该维度用50，其余正常加载
  - 维度缺失 → 缺失维度补50

### M-003：记忆写入幂等性
- 相同 `content + layer` 已存在 → 更新时间戳，不创建重复记录
- 写入前先 `find_by_content` 精确匹配

### M-004：审计日志集成
- 所有读写操作记录到 `AuditLogger`
- 写入被拒绝（只读模式）也记录，`success=False`

### M-005：只读模式
- `MemoryManager(read_only=True)` 时拒绝所有写入
- 读取操作不受影响

### M-006：人格权重调整（PID 控制器）
- 科学依据：控制论 Ziegler-Nichols 方法
- 公式：`u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt`
- 参数：`Kp=0.5, Ki=0.1, Kd=0.05`
- 死区：5.0（偏差 < 5 不调整）
- 单次最大调整量：10.0
- 积分项上限：50.0（防积分饱和）

### M-007：personality.md 文件格式

```markdown
| 维度 | 分值 | 说明 |
|------|------|------|
| H | 70 | 诚实-谦逊 |
| E | 40 | 情绪性 |
| X | 60 | 外向性 |
| A | 55 | 宜人性 |
| C | 80 | 尽责性 |
| O | 65 | 经验开放性 |
```

### M-008：存储方式
- `MemoryManager` 直接操作 SQLite 数据库（通过 `storage/` 目录）
- 当前实现：`src/memory/storage/` 下的 SQLite 实现
- V2 如需切换 Redis，需新增 storage 实现（当前未启用）
