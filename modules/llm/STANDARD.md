## 一、模块定位

LLM 调用层是 Agent 的"语言中枢"，负责模型路由、Prompt 组装、错误处理和模型回退。

**核心约束（主心骨）**：
> **抽象接口与实现分离。ModelRouter 管理回退链 + 冷却机制，PromptManager 管理模板 + 动态组装。主模型不可用时自动回退到备用模型。所有参数（超时/重试/冷却时长）由 LLM 动态评估或用户指定，禁止写死。**

## 三、模块规则

### L-001：ModelRouter — 模型路由

**回退链**：
- 主模型不可用 → 按 priority 顺序切换到备用模型
- 用户可手动切换模型
- 不做任务分级路由（用户选什么就是什么）

**冷却机制**：
- 模型被限流时自动进入冷却期
- 冷却期间跳过该模型
- 冷却时长由 LLM 根据限流响应头动态评估（非写死）

**模型注册**：
- `register_model()` 注册时必须提供 `api_key`（G-001 配置外部化）
- `priority=0` 为最高优先级
- 模型可用性由 Provider 在运行时验证，不在注册时限制模型列表

**状态可观测**：
- `get_status()` 返回当前模型、回退链、冷却状态、统计
- 供 UI 显示

### L-002：PromptManager — Prompt 管理

**模板管理**：
- 提示词模板存储在第3层记忆（标准层）
- 支持 CRUD 操作
- 支持多版本和 A/B 测试

**动态组装**：
- 根据上下文动态组装 system prompt
- 注入顺序：基础信息 → 人格参数 → 相关记忆 → 当前标准 → 用户输入
- 上下文窗口预算分配：动态计算各部分 token 占比

**内置模板**：
- `system_base`：基础系统提示词（时间 + 用户ID）
- `with_personality`：含 HEXACO 人格参数
- `intent_analysis`：意图分析

### L-003：错误分类 + 精准重试

| 错误类型 | 是否重试 | 处理方式 |
|----------|----------|----------|
| 超时 | ✅ 重试 | 指数退避 |
| 限流（429） | ✅ 重试 | 冷却 + 切换模型 |
| 认证错误（401） | ❌ 不重试 | 立即报错 |
| 模型不存在（404） | ❌ 不重试 | 切换模型 |
| 内容过滤 | ❌ 不重试 | 返回提示 |

### L-004：V2 升级方向
- Prompt 存在第3层记忆 + Thompson Sampling 优化
- Prompt 渲染（变量注入 + 记忆上下文）
- 跑偏检查（利用 LLM 做执行偏离检测）
- 上下文窗口预算动态分配
