## 一、模块定位

安全模块是 Agent 的"免疫系统"，保护用户数据、防止危险操作、管理凭证安全。

**核心约束（主心骨）**：
> **三道防线纵深防御：SecurityGuard（输入/输出过滤）→ ApprovalModule（危险操作审批）→ ConflictChecker（知识冲突检测）。安全默认，审批是强制卡点不是建议。所有检测模式可由 LLM 动态更新。**

## 三、模块规则

### S-001：SecurityGuard — 三道防线

**防线1：输入过滤（提示词注入检测）**
- 检测模式：正则匹配（基础模式 + LLM 动态扩展）
- 命中 → 返回 `SecurityCheckResult(is_safe=False, threat_type="prompt_injection")`
- 基础模式：`ignore previous instructions`、`you are now a`、`jailbreak`、`DAN mode` 等

**防线2：路径检查（路径遍历防护）**
- 检测 `../`、`..\\`、`%2e%2e`、`/etc/passwd`、`/etc/shadow` 等
- 命中 → 返回空路径 + 不安全标记

**防线3：输出检查（敏感信息泄露检测）**
- 检测 API Key（`sk-...`）、password、secret 等模式
- 命中 → 自动脱敏（替换为 `[REDACTED]`）

### S-002：ApprovalModule — 三级审批

| 级别 | 触发条件 | 处理方式 |
|------|----------|----------|
| L1 自动通过 | 低风险操作（读取、查询） | 无需审批，直接执行 |
| L2 确认后执行 | 中风险操作（写入记忆、修改配置） | 需用户确认 |
| L3 强制审批 | 高危操作（删除、部署、清空记忆、重置人格） | 不审批就不执行 |

- 风险评分由 LLM 根据操作描述动态评估（非写死）
- 审批超时（默认 3600 秒）自动取消
- 审批状态：PENDING / APPROVED / REJECTED / TIMEOUT / CANCELLED

### S-003：ConflictChecker — 知识冲突检测
- 写入新知识前，检查与已有知识是否矛盾
- 冲突判定：Jaccard 相似度（集合论, 1901）+ 自指性检测
- 有冲突 → 标记冲突 + 拒绝写入 + 提示用户
- 冲突检测在 `MemoryManager.remember()` 之前执行

### S-004：CredentialPool — 凭证安全
- 所有凭证通过 Fernet 加密存储（复用 config 模块的加密函数）
- 凭证不打印到日志
- 凭证缺失时向用户申请，不编造（G-010）

### S-005：所有参数不写死
- 风险阈值（low/medium/high）：由 LLM 根据操作描述动态评估
- 审批超时：默认 3600 秒，可由 LLM 根据操作复杂度调整
- 检测模式：基础模式 + LLM 动态扩展
