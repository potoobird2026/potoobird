# ADR-006：上下文压缩算法选型（已更新）

> **状态**：已更新（2026-05-04）
> **变更**：原方案 B（三阶段压缩）已升级为双锚点保边 + 10算法融合评分 + 幂律裁剪


## 状态：已接受

## 背景
Agent 对话历史会不断增长，超出 LLM 上下文窗口。需要压缩策略。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 简单截取 | 取最近 N 条 | 最简单 | 丢失重要历史 |
| B. 三阶段压缩 | 评分→裁剪→摘要 | 保留重要信息 | 复杂度高 |
| C. 全部摘要 | LLM 压缩所有历史 | 信息损失最小 | 每次对话都调 LLM，贵 |

## 决策
**方案 B：三阶段压缩**

1. **评分**：对每条消息打价值分（重要性、时效性、信息密度、相关性）
2. **裁剪**：按幂律分布裁剪低价值消息
3. **摘要**：LLM 语义压缩保留实体、关系、意图

所有参数不写死，由公式/LLM/用户互动三个维度获得。

## 理由
- 简单截取丢失太多重要信息
- 全部摘要成本太高
- 三阶段在质量和成本之间平衡
