# ADR-009：动态记忆加载算法

## 状态
Accepted

## 日期
2026-05-03

## 背景
V1 的记忆加载使用粗暴截取（最近 N 条），缺乏信息论依据：
- 不相关的记忆被加载，浪费 Token 预算
- 高价值但未最近访问的记忆被遗漏
- 无预算分配机制，加载数量拍脑袋

## 决策
采用基于信息论的记忆动态加载算法：

### Token 预算分配

```
总预算 = ModelConfig.context_window
├── 热区 40%：最近访问的记忆（access_count 高 + last_access_at 近）
├── 相关 30%：与当前输入互信息 I(X;Y) 最高的记忆
├── 高价值 20%：香农熵 H(X) 最高的记忆（信息量大）
└── 锚点 10%：不可淘汰的锚点记忆（实体定义、人格核心）
```

预算比例来源："开始的上下文.txt" §Token预算分配

### 信息论指标

| 指标 | 公式 | 用途 |
|------|------|------|
| 互信息 | I(X;Y) = H(X) + H(Y) - H(X,Y) | 衡量记忆与当前输入的相关性 |
| 香农熵 | H(X) = -Σ p(x) log p(x) | 衡量记忆的信息量 |
| KL散度 | D_KL(P‖Q) = Σ P(x) log(P(x)/Q(x)) | 衡量记忆与当前输入的分布差异 |

### 热区评分公式

```
hot_score = 0.5 * freq_score + 0.5 * recency_score
- freq_score = min(1, log(1+access_count) / log(100))
- recency_score = exp(-0.693 * age_hours / 24)  （半衰期 24h）
```

### 淘汰触发公式

```
eviction_score = (N / K) ^ α
- N：当前记忆数量
- K：容量上限（默认 10000，SQLite+FTS5 实测经验值）
- α：幂律裁剪指数（默认 1.5，Clauset et al., 2009）
- 触发条件：eviction_score > 0.85
```

### 锚点保护
以下记忆不可淘汰：
1. layer == "personality"（人格层）
2. is_anchor == True（显式标记）
3. 包含实体定义关键词（"叫"、"名为"、"定义为"等）

## 后果
- ✅ 加载决策完全由公式驱动，无魔法数字
- ✅ Token 预算合理分配，高价值记忆优先
- ✅ 锚点记忆永久保留，不会误淘汰
- ⚠️ 互信息计算使用 Jaccard 简化版（精确计算需要大规模语料库）
