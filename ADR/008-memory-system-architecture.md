# ADR-008：记忆系统联动架构

## 状态
Accepted

## 日期
2026-05-03

## 背景
V1 的记忆系统各模块独立运行，缺乏联动：
- ContextCompressor 已实现但未被主循环调用
- 记忆加载使用粗暴截取，无信息论依据
- 记忆淘汰无策略，仅靠容量硬限制
- 写入策略与淘汰策略不匹配（严进宽出）

## 决策
采用"宽进严出"的记忆系统联动架构：

### 核心设计哲学
- **写入不过滤**：写入成本极低（一条 SQLite INSERT），不应限制
- **淘汰看价值**：淘汰成本极高（永久丢失信息），必须按价值淘汰
- **加载按预算**：Token 预算有限，必须按信息价值分配

### 三个组件联动

```
用户输入 → [MemoryLoader] → 按预算动态加载记忆
                ↓
         [MemoryManager] → 构建 System Prompt
                ↓
         [MemoryEvictor] → 淘汰低价值记忆
                ↓
         [LogisticGrowth] → 容量管理（宽进严出）
```

### 组件职责

| 组件 | 职责 | 核心公式 |
|------|------|---------|
| MemoryLoader | 动态加载记忆（按 Token 预算） | 热区40%+相关30%+高价值20%+锚点10% |
| MemoryEvictor | 淘汰低价值记忆 | eviction_score = (N/K)^α，复用10算法评分 |
| LogisticGrowth | 容量管理（宽进严出） | P(write)=1.0, P(evict)=(N/K)^α |

### 参数来源
- α = 1.5：幂律裁剪指数（Clauset et al., 2009），LLM 动态调整
- K = 10000：SQLite + FTS5 实测经验值
- 预算分配比例：来自"开始的上下文.txt" §Token预算分配

## 后果
- ✅ 记忆系统各模块形成闭环
- ✅ 写入不丢失信息（宽进）
- ✅ 淘汰有据可依（严出）
- ✅ 加载按预算分配（高效）
- ⚠️ 需要 LLM 动态调整 α 参数
