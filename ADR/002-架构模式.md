# ADR-002：架构模式 — 7 步循环 + 状态机驱动

## 状态：已接受

## 背景
Agent 需要一个清晰的主循环架构来调度各模块。需要决定：循环步骤划分、状态管理方式、错误恢复策略。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 简单 if/else | 线性流程，无状态机 | 简单 | 无法处理跳转/重试/暂停 |
| B. 7 步循环 + 状态机 | 每步对应一个状态，状态机管理转换 | 清晰、可扩展、支持跳转 | 复杂度中等 |
| C. 事件驱动 | 完全事件驱动，无显式循环 | 灵活 | 调试困难，MVP 过度设计 |

## 决策
**方案 B：7 步循环 + 状态机驱动**

7 步：
1. 感知（PERCEIVING）— 读取输入 + 加载上下文
2. 理解（UNDERSTANDING）— 意图解析 + 置信度评估
3. 规划（PLANNING）— 确定操作类型 + 审批检查
4. 执行（EXECUTING）— 调用 LLM / 工具 / 写入记忆
5. 观察（OBSERVING）— 检查结果
6. 反思（REFLECTING）— 更新记忆 + 触发后台任务
7. 回复（REPLYING）— 格式化输出

## 理由
- 步骤清晰，每个步骤职责单一
- 状态机管理跳转（追问、重试、暂停审批）
- 与 DESIGN.md 中的状态设计对齐

## 后果
- 需要维护状态转换表
- 步骤方法不能随意跳转，必须通过状态机
