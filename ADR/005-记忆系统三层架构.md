# ADR-005：记忆系统 — 三层架构

## 状态：已接受

## 背景
Agent 需要持久化记忆，但记忆有不同的变更频率和敏感度。

## 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 单层 SQLite | 所有记忆存一张表 | 简单 | 无法区分变更频率 |
| B. 三层架构 | 人格层(只读) + 核心层(SQLite) + 标准层(Markdown) | 按频率分离、安全 | 复杂度中等 |
| C. 向量数据库 | 全部向量化存储 | 检索能力强 | MVP 过度设计 |

## 决策
**方案 B：三层架构**

| 层 | 存储 | 变更频率 | 内容 |
|----|------|---------|------|
| 第1层：人格 | personality.md (只读) | 几乎不变 | HEXACO 人格参数 |
| 第2层：核心 | SQLite | 每次对话 | 用户偏好、关键事实 |
| 第3层：标准 | Markdown | 低频更新 | 开发标准、规则 |

## 理由
- 不同层有不同的变更频率，分离后互不干扰
- 人格层只读，防止意外修改
- 核心层 SQLite，支持快速检索
- 标准层 Markdown，人类可读可编辑
